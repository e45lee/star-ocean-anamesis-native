# Audit (2026-09-30): native code that is mechanically translated ARM64

`linux-port` at 615dcc2. This lists the native C++ that is **not a real port**: guest ARM64 functions translated instruction by instruction by `tools/a2c.py`. That code is ARM64 wrapped in C++. Each body works on an emulated register file (`A64& r`: `x0..x30`, `v0..v31`, flags) and uses guest memory through load/store macros. It keeps the guest's control flow, stack frame and calling convention, so it is exact but not readable, and it still depends on the guest image's layout and data.

## How it was counted
- **Translated body** (since D8 these files live in `port/src/native/<subsystem>/gen/`): any function with the signature `(A64& r)` in a file whose header says `GENERATED by tools/gen_*_a2c.py` / `a2c.py`. Regenerate the count with:
  ```sh
  cd port/src/native && for f in $(grep -rlE --include='*.cpp' --include='*.inc' '\(A64& r\) *\{' .); do
    head -3 $f | grep -q GENERATED && echo "$f $(grep -cE '\(A64& r\) *\{' $f)"; done
  ```
- **Registered translated natives:** entries of `build/port/soa --list-native` whose description carries `(a2c)` or `(transcribed)`.
- **Readable overrides:** readable C++ (`*_rd*.cpp`) that a translated body dispatches to by default. The translation stays in the tree as the reference, and each family has a switch back to it.

## What is *not* in this list
- **Real ports:** readable C++ natives, e.g. the 4,767 `models (readable)` template instances (`models_anim.cpp`, the `TAaf*` animation templates), battle, gacha, server-facing code, UI screens written by hand, `CParameter*` / master-data code, libc++ helpers.
- **Hand ports that are readable but still layout-bound:** readable, but they access guest objects by byte offset (for example `*(u32*)(obj + 0x1a0)`). They are not ARM64-wrapped. Turning offsets into structs is roadmap §5 step 9 (`REMAINING.md`).

## Where the translated code costs the most
From the C-4 host profile (`SOA_PROFILE_HOST=1`, `port/scripts/host_profile.py`, `restore_session.sh`):
- `ShadowManager::ShadowCasterCulling` (render, 32 KB): the hottest remaining translated body, about 210 self samples.
- `AofObject::PrepareForRendering`, `PrepareForRendering_Preliminary`, `GetColorPass`, `CalcAndSetSubFunctor`, `LightManager::MakeLightContext`: about 45–55 each.
- Call dispatch into translated code: `models_gcall` (~136) and the body table (~150).

## Suggested order for the readable rewrite (Track C)
1. objbase (C-3): verification just finished, and 148 bodies are installed.
2. render hot spots: `ShadowCasterCulling`, then the `AofObject` render path and `MakeLightContext`.
3. infobase: 385 bodies from one generator; replace them with one C++ template over the element type.
4. containers: 465 bodies, mostly `TDynamicArray` / `TPoolFast` / `THashMap` instantiations; rewrite them as templates over the element type.
5. models: the remaining bodies (`SkinMatrices*`, the hierarchy walk and the Aof render context are done).
6. Cocos, the guireader and screens: UI code; lower heat, large bodies.
7. aska math: small FP functions; many already have bit-exact helpers.

Every rewrite keeps the translation as its reference, with a switch back to it. It also needs a differential selftest that catches planted bugs, plus the family's live check at 0 mismatches.
