# libSOA.so 3.7.0 (online) vs 3.8.0 (offline)

> History: written when the port ran the offline 3.8.0 library with 3.7.0 behaviour restored on top; the port no longer uses 3.8.0 (it runs the 3.7.0 client). Current docs: [README.md](../../README.md), [port/README.md](../../port/README.md); the 3.8.0 client is only run by the viewer ([emulator-viewer/README.md](../../emulator-viewer/README.md)).

What changed in the game library between the last online client, **3.7.0** (`work/libSOA-3.7.0.so`, from the 3.7.0 APK), and the offline "service ended" client, **3.8.0** (`work/extracted/config.arm64_v8a/lib/arm64-v8a/libSOA.so`, the library the port runs). Section 2 also covers how the port answers each change under `--restore`.

The doc builds on these, and doesn't repeat their details:
- `tools/verdiff.py`: the version-diff tool. Its output (`work/verdiff/`) is the raw material here.
- [`docs/notes.md`](notes.md) "3.7.0 vs 3.8.0: what the offline build changed": the method, the per-feature summary and the layout check.
- [`docs/client-changes.md`](client-changes.md): every place the port changes or restores client behaviour, with switches and reasons.
- `port/src/native/restore370.{h,cpp}`: the restore image, which runs 3.7.0 bodies on the 3.8.0 symbols.
- [`docs/online-server.md`](online-server.md): the online stack that 3.8.0 no longer uses.

**Where each claim comes from:**
- **[D]**: read in the Ghidra decompiles of both builds. Either this doc's own `work/decomp/verdiff-doc-v370.resolved.c` / `verdiff-doc-v380.resolved.c` (regenerated by the commands in section 5), or the decompiles cited in notes.md / client-changes.md.
- **[V]**: from verdiff's normalised instruction diff: calls, strings, constants and sizes added or removed. It's reliable about *what* differs, but it doesn't say why.
- **[I]**: inference: the purpose of a change, or a reading of names and call structure that wasn't followed all the way.
- **[data]**: read from the master DBs or the APKs.

Addresses are ELF vaddrs unless marked Ghidra (vaddr + 0x100000).

### What 3.8.0 is
The Japanese service closed on 2021-06-24. 3.8.0, built 2021-06-07, is the build Square Enix shipped so the game could still be played without a server ("stand-alone", the `SA` / `StandAlone` suffixes in new names) [I, from names and dates]. Its changes fall into five kinds:
1. **Online flows cut or short-circuited.** The login, account creation, tutorial, relogin and server-time phases, the party-building screen, the adjutant select, the mission hand-over into battle, and scene-end reporting. Offline, `NoLoginStart` is the only request left ([notes](notes.md) "API calls").
2. **Local replacements for server data.** The master-data lists (`RequestListLocal`, `CreateStoryListFromSqlite`, `GetCharacterListForSA_FromMasterIdList`, `…MissionLocal`), and local-KVS flags for the new player, the terms of use and the sort / menu-voice migrations.
3. **The clock frozen at the end of service.** `master_global.service_stop_day` = `2021/06/24 14:30:00`.
4. **Platform services stubbed.** Google Play Games achievements and sign-in, local notifications, GPS / location, and online web pages (replaced by local HTML).
5. **Play Asset Delivery added.** The downloadable asset set ships inside the XAPK as an install-time asset pack, read through Google's `playcore` library.

The battle code, the API response handlers (`CApiNotify`), the request serializers, the master-parameter loaders and all vtables of classes present in both builds are unchanged ([notes](notes.md) "Unchanged").

## 2. Changed functions by subsystem

Each group says what changed and why, then the port's response:
- a **restore370 group**: the 3.7.0 body runs on the 3.8.0 symbol under `--restore` (`port/src/native/restore/restore370.cpp`; client-changes.md "Restored 3.7.0 code");
- a **server-side answer**: the local server supplies the data the unchanged client expects;
- a **client change**: a native wrapper or patch, logged in client-changes.md;
- **not needed**.

Everything under `--restore` is off by default; the default game is the unchanged offline 3.8.0.

### 2.1 Network / API caller
- **`NetworkApiCaller::BeginBridge`** [D]: 3.7.0 first checked a "bridge ready" flag at `this+0xc80` (`param_2[400]`) and a virtual query (vtable +0x6a0). If both held, it copied the player id from `CParameterPlayer` (+0x38) into the caller (+0x28) and completed the callback with status 0 at once, without a network round-trip. 3.8.0 always starts a new bridge: keep-alive, UUID, `SendStartBridge` (fid `0xd4053e85`). The rest of the body is the same code.
- Nothing else in `NetworkApiCaller`, `CApiNotify`, the `GameProtocolProxy` serializers or `ErrorHandler` changed [V]. The offline build still contains the whole online client; it just stops calling most of it. So the wire format in [online-server.md](online-server.md) / [api.md](api.md) holds for both builds.
- **Port:** not needed. The port serves requests on its `FakeApiCaller` route and never opens a bridge.

### 2.2 Login, title and new player (38)
- **`CPhase_Login::Progress`** (4,496 → 4,284 bytes; 6 lambdas changed) [V, D in client-changes.md]:
  - Removed: the online login state machine (`Login`, error 19001 → new player → terms → name entry → `CreatePlayer` → `SettingForNewPlayer`), the terms-version check (`UpdateKiyakuVersion`), `SetLocalKVSPlayerID`, `SetMissionRestart(0)`, `CPaymentManager::Initialize`, the select-all-download query, and the call to `CPopupManager::AddPopup()` that armed the post-login popups.
  - Added: a local new player. It is created when the stored id is a placeholder (`IsLocalKVS_StandAloneNewPlayer`), with level 1, stamina 10 and the three starter roles `offline_Character_1..3`, a `master_global` key that only the 3.8.0 DB has. Then the terms of use (`BAS:StandAloneTermsOfUse`) through `CPlayerInitializeMenu`, then `CPhase_DataDownload`.
  - `CPhase_Login` grew 0x28 → 0x30 bytes (a flag at +0x28, which the constructor zeroes).
  - **Port:** restore370 `login` (Progress and both constructors), answered by the local server's `Login` / `CreatePlayer` / `UpdateKiyakuVersion`.
- **`CPlayerInitializeMenu`** (`Initialize` 3,608 → 2,180, `Setup`, `Progress`, `OpenUsesGuideConfirm`, `OpenUsersGuidView` lambda) [V]: the terms / name-entry dialog was cut to the stand-alone terms prompt (no `Button_center_close`); a lambda now sets the new-player / terms KVS flags. **Port:** restore370 `playerinit`.
- **`CTitle::Setup`** (3,068 → 1,584; 5 lambdas) [V, D in client-changes.md]: the player-id display, the resource-cache check (`CGameResourceDownloader::IsExistCache`), the update panel, the service-end dialog (`uimsg_service_end_dialog`), the title-movie button and the 紋章石払戻し refund (`Button_refund`, `PayBackConnect`) are gone. **Port:** restore370 `title`, **off by default** (`SOA_RESTORE370_ON=title`): on the 3.8.0 `CTitle::Progress` its tap-to-start chain never reaches `StartGame`.
- **`CTitle::Progress` / `StartGame` / `ToRelease` / `CTitle()`**: only the title menu-voice id changed, `0xd` → `0x13`, because `CUIVoiceManager::MenuID` was renumbered (2.10) [V]. The `Progress` lambda #0 lost 3.7.0's node set-up before `PlayTapToStart` [V]. **Port:** kept 3.8.0; their 3.7.0 bodies would play the wrong voice.
- **`CPhase_DataDownload::Progress`** (group 2.13) dropped the old-version-file migration.

### 2.4 Clock: `service_stop_day` (35)
- **`CTimeUtility::NowTime`** [D]:
  - 3.7.0: `BAS::LocalTime()` (i.e. `time()`) passed through `CServerTime::FixTime` (adds the server offset).
  - 3.8.0: looks up `master_global.service_stop_day` (`FindGlobalStringWithKey`). If the value is non-empty it returns `str2time_t(value)`; otherwise `FixTime(LocalTime(true))`.
- **`BAS::LocalTime()` → `BAS::LocalTime(bool)`** [D]: with `true` it does the same `service_stop_day` check before falling back to `time()`. `CTimeUtility::NowTimeTrue` now calls `LocalTime(true)`, so even the "true" time is frozen. `CServerTime::FixTime` itself is identical.
- **30 time helpers** now call `NowTime()` where 3.7.0 inlined `FixTime(LocalTime())` [V, D for `IsWithinDay`]: AP regeneration (`NowAp*`, `*ApRemainSec*`), remaining-time and "before" texts, `IsSameDay` / `IsSameMonth`, `NowDate*`, `IsWithinDay*`, footer badges, coin sales, gacha sale type, ship counts, event-ranking groups, limit-break lists, and the notice / guide KVS dates.
- **The only-signature-changed callers:** `CServerTime::SetLocalTime` / `UpdateServerTimeOffset`, `CHomeUtility::GetHomeParameter`, `CGame::OnPause` / `OnResume` [V].
- **Other readers of `service_stop_day`** (3.8.0): `CCharacterPictureBook::CreateCollectList`, `CHome::GetAdjutant`, `CAdjutantSelect::CreateCharaList`, `CTitle::Setup`, `CPhase_Server::CPhase_Server` (client-changes.md).
- The row is in **both** DBs; 3.7.0's code just never reads it [data, D].
- **Why** [I]: with no server there's no trustworthy time. Freezing the clock at the last online moment keeps every time-limited item (events, sales, gachas, AP) consistent with the final master data.
- **Port:** a server-side answer. Under `--restore` the local server deletes the `service_stop_day` row from the client's in-memory master copy, so `NowTime` takes 3.8.0's own live-clock path with the server offset from `data.Time` (client-changes.md "Data overrides").

### 2.8 Favorability (10)

### 2.12 Platform services and web views (38)
