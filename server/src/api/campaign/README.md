# api/campaign: the story campaign

Public header `soaserver/api_campaign.h` (`campaign::enabled`, `on_request`, `on_response`, `end_mission_talk`, `active_mission_list_msgpack`); internal header `campaign.h`.

| File | What |
|---|---|
| `campaign.cpp` | the hooks: `record_progress`, its `OnResponse` hook (`register_campaign`; an accepted MissionStart / MissionEnd / MissionTalk: the mission playing, a clear, in the request's transaction); around each request, called by `server::answer` (`core/lifecycle.cpp`) for both hosts: `on_request` (the log lines, the session's world-map episode), `end_mission_talk` (a story scene's end, in the live server's own transaction), `on_response` (`campaign_keys`: Player, ActiveWorldMapMissionList, ActiveMissionList spliced into the body); the splice on `Value` (`decode_body`, `splice_data`, `merge_maps`: a body that doesn't encode back to the same bytes is left alone) |
| `master_data.cpp` | the campaign's master tables, read once by its own SQLite handle (`open_master`: --campaign-master-db, else the server's master, else the repository's 3.7.0 DB): `load_missions`, `load_areas_and_planets`, `load_stages`, `load_world_map` |
| `progress.cpp` | the player's progress (`State`: cleared missions, the last play, the clock), read from the state DB's `campaign_clear` / `campaign_last` each time (`load_state(ctx)`; PLAN-schema S12; until version 11 the file `<data>/server_campaign.txt`, which the schema's step 11 imports); `--campaign-seed` (`seed_chain`: added when read, saved with the first clear); `clear_mission(ctx, ...)` writes in ctx's transaction |
| `lists.cpp` | what is listed: `available` (Episode 1: the unlock chain, the story areas, the windows; the world map: `world_map_available`, `group_open`, `episode_progress`), `build_active_mission_list` (ActiveMissionList), `build_world_map_list` (ActiveWorldMapMissionList), `build_player` (Player.world_map_progress*, a seeded player's view_status*); `in_window` (a string compare: a variant of `core/time.h` `open_at`, kept apart) |
| `campaign_tests.cpp` | `campaign/unlock-chain` (the Episode 1 chain against the master data), `campaign/splice` (the splice's order and refusal rules on bytes) |

**A module with one hook:** `register_campaign` (last in `core/modules.cpp`) adds the `OnResponse` hook that records progress; no `Api`. Its keys are spliced around each request, after every hook's. **State:** the state DB's `campaign_clear` / `campaign_last` (`server/src/state/README.md`, step 11), read for every answer and written in the request's transaction (a refused request records nothing); nothing of it is kept in memory. The session's volatile bits (`Session`: the mission playing, the world-map episode) are under the campaign's lock, a leaf lock never held while taking the server's.

**Rules**: docs/server-rules.md#campaign. **Proof and sessions**: every replay corpus (the campaign runs on every request; `campaign`: clears, story scenes, the world map; `seeded` with `--campaign-seed mf01_001`, the `tutorial`'s scenes); `port/scripts/campaign_session.sh`, `restore_missions.sh`.
