# server/src/core: the server object, the request lifecycle, the module registry

The library's core: the server object, the request lifecycle, the module registry and the shared helpers; no game rule of a single domain lives here (the core's APIs are in `../api/<domain>/` since step R8 of `../../PLAN-readability.md`). Public API: `../../include/soaserver/server.h` (requests, clocks), `ext.h` (the module API), `log.h`, `config.h`, `battle_log.h`.

| File | What |
|---|---|
| `server.cpp` | `struct Server` (declared in `server.h`): the state and master DBs, the gacha pools, the pending requests, one transaction per request (`handle_request`), the refusal path and `Server::dispatch` (the registry's handler of the method; the core's APIs are in `../api/<domain>/`, registered with `ext::add_core_api`); `make_ctx` (a request's `ext::Ctx`); the state's meta helpers (declared in `server.h`); the public request API of `soaserver/server.h`. Its tests: `server_tests.cpp` (a whole session on a scratch state; the response encoder) |
| `lifecycle.cpp` | the request lifecycle both hosts use: `answer(Request, fallback)` (EndMissionTalk; `submit`, the story campaign's `on_request`, `handle`, `error_code`, the campaign's `on_response`) and `end_mission_talk(mission)` (`soaserver/server.h`) |
| `context.cpp` | `ext::Ctx`'s services (`now`, `event_now`, `base_data`, `roster`, `stock`, `items`, `grant`, `core_mission`, `set_error`, ...): plain functions over the request's DBs and `RequestContext` |
| `server.h` | the server object (`struct Server`, its `Db`) and the core's internals its other files use: `file_exists`, `first_existing`, the state's `meta` / `set_meta` / `next_uid` / `has_player` (PLAN-schema S1 moves them to `state/`), `one_null_as_zero` (the core's NULL-reads-as-0 `one()`), `event_clock_of` |
| `rewards.{h,cpp}` | granting a content (`grant`: items, characters, FOL, coins, stack items, else the modules' `Grant` hooks) and adding a character (`add_character`: a duplicate raises the owned one's limit break, beyond it the duplication material); `Drop`, `Added`. `ext::Ctx::grant` is `grant` with drop type 0; `grant_with_item_sets` expands item sets (content type 99, `kContentTypeItemSet`) and tallies free coins (the shop, the exchange and the event ranking rewards; R18) |
| `ids.h` | the uid scheme of owned objects (`kRosterUid0`, `kNewCharUid0`, `kItemUid0`); typed ids join them in R12 |
| `request_context.h` | `RequestContext`, the state of the one request being answered (its refusal code, battle log, `live`, `test_log_value`, `logged_in`, the titles it granted); `ctx.request` in every handler (ARCHITECTURE.md "One handler shape") |
| `ext.cpp` | the module registry (`ext::add_api` ..., `find`, `player_load`, `on_response`, the hook order record), the SQLite wrapper `ext::Sql`, the shared state helpers (counters, presents; stocks and FOL forward to `wallet`). Split by R6 / R7 |
| `modules.{h,cpp}` | the modules' one registration order (`register_all`, ARCHITECTURE.md "The module registry and its order"); `modules_tests.cpp` pins it |
| `time.{h,cpp}` | the local-time helpers, one copy each: `format_time` (public, `soaserver/server.h`), `format_time_or_empty`, `parse_time` (lenient), `parse_time_strict`, `parse_time_or_epoch` (`--clock`), `parse_day_and_time`, `day_start(t, reset_hour)`, `add_years`, `year_of`, `Window` / `open_at` (a dated master row's opened_at..closed_at); `time_tests.cpp` pins how the variants differ |
| `errors.h` | **generated** by `tools/gen_error_codes.py` from the 3.7.0 master's `error_message_text_<code>`: `enum class ErrorCode` (the 13 codes the server refuses with, each with the client's text and why that code) and `ext::refuse(..., ErrorCode)`; the client's other codes as a comment table. `tools/check_server_docs.sh` checks it is fresh |
| `response.{h,cpp}` | the one response envelope `ext::body` (`{data, status}`), `ext::with_player_state` (the `{Time, Player, Wallet}`-only answer) and `ext::refuse` / `ext::refusef` (the one refusal path, core and modules alike: logs `<Method> refused: <why> (error N)`, records the code in the request's `RequestContext`, answers the player state) |
| `wallet.{h,cpp}` | the wallet, one copy of each rule: coins (`coins`, `split` (free coins first, or paid only), `covers`, `take`, `spend_coins`, `add_free_coins`), FOL (`fol`, `add_fol`: floored at 0, capped at `item_fol_max_num`), stack items (`stock_count`, `add_stock`: capped at `item_stock_max_num`); `ext::fol` / `add_fol` / `stock_count` / `add_stock` forward to it |
| `request_args.h` | the core handlers' arguments by name (`args::MissionStartArgs::from(r)` ...; `int_at` / `str_at`), with the defaults the handlers had (UpdateParty's party 1, BoxGacha's count 1, CreatePlayer's "Player") |
| `assets.{h,cpp}` | the one asset gate: `available(rel)` (the tests' one override, else everything without an asset source, else `found`), `found(rel)` (the host's `AssetIndex` under builtin_data/ and assetpack/ with the quality subdirectories), `set_override` (= `events::set_asset_check` = `sphere211::set_asset_check`) and `generation()` (verdict caches start over when the override changes) |
| `clock.cpp` | the server clock (`clock_now`, `set_server_clock`, the test seam `set_clock_source`) and the event calendar (`event_now`: today's date replayed onto the service years; docs/server-rules.md "Clocks") |
| `log.h` | the `LOG*` macros the library logs with (the sink is `soaserver/log.h`) |
| `battle_log.cpp` | the ASON battle log MissionEnd and co. carry (`soaserver/battle_log.h`) |
| `support.cpp` | the configuration (`config()`), the log sink, the asset index, CHash32. Split by R6 (config, log, asset index, chash32) |

Tests: `soa-server --selftest "server/"` (the core's are named `server/...`).
